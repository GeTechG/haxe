## Why
Nothing checks this fork's OpenSpec: the CLI version is not pinned (agents used whatever global `openspec` they found), the repository carries no OpenSpec skills, so changes were written by hand (none of the 12 archived changes has `.openspec.yaml`), and `openspec validate --all --strict` of OpenSpec 1.16.0 finds seven requirements longer than 500 characters in six specs.

## What Changes
- `openspec/cli.pin` holds the one OpenSpec version the fork uses (`1.16.0`); CI runs that version, and AGENTS.md says how to raise it.
- The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify) are generated by the pinned version into `.claude/skills/` and `.agents/skills/` and committed; new changes are created by `openspec new change`.
- A new CI job validates OpenSpec with the pinned version: strict validation of specs and active changes, no `TBD` Purpose in a main spec, `.openspec.yaml` in every active change, skills generated by the pinned version, no open task but a `[human]` one in an archived change.
- `openspec/config.yaml` gains `rules.specs`, `rules.tasks` and `operations.apply` / `operations.archive` guidance that points at AGENTS.md.
- The seven long requirements are rewritten so each states one behaviour within 500 characters; details move into scenarios of the same requirement, nothing of their meaning is dropped.

## Capabilities

### New Capabilities
- `openspec-checks`: the pinned OpenSpec version, the skills it generates, and the CI checks of `openspec/`.

### Modified Capabilities
- `commit-kinds`: the requirement on mixed commits is shortened; behaviour unchanged.
- `display-references`: the requirement on candidate files is shortened; behaviour unchanged.
- `eval-sys-errors`: what is not covered, and an uncaught exception, move into scenarios; behaviour unchanged.
- `hlc-identifiers`: which headers and names are covered moves into scenarios; behaviour unchanged.
- `server-connect`: the environment requirement is shortened, the process requirement is shortened, its Windows and `haxelib` exceptions and the requests without an environment move into scenarios; behaviour unchanged.
- `structural-search`: the requirement on provisioning is shortened, the order of the tool checks moves into a scenario; behaviour unchanged.

## Impact
Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/skills/`, `.github/workflows/ci.yml`, `AGENTS.md`. No code path, compiler behaviour or build key changes. CI needs npm to fetch `@fission-ai/openspec` at the pinned version.
